# 多组织、多项目的网页结构

2026-10-12：本文是此前组织管理方向与旧路由的历史约定。当前改为本地设计体系编辑工具，组织结构与地址待重新评估，不作为新开发前提。当前入口见 `handoff.md`（交接说明）。

这份说明记录本次确定的网页架构方向。用户主要手工写代码，当前只做源码阅读和结构约定，没有修改正式页面或安装路由依赖。

## 页面分成两层

组织层管理项目，项目层使用设计工具。进入组织时展示项目列表；点击项目后，进入它自己的主页和侧栏。顶部始终能看见组织，在项目内再显示当前项目。

支持创建、切换多个组织，每个组织有多个项目。这版先做单人管理，成员邀请、角色权限和计费不在当前步骤中。

主页指项目主页，负责初始化说明、命令和检测结果。组织首页是项目列表，两者不能继续混称一个主页。

## 路由约定

路由就是浏览器地址与页面之间的对应关系。已和用户确定保留现有网页框架，引入 `React Router`（React 路由库），不引入 `Next.js`（React 全栈框架）。此前“不加路由库”的约定被本次需求替代，不增加其他状态库。

实现准备采用第 7 版的声明式模式：使用组件声明地址和页面的对应关系。它可以直接用于当前开发工具，不需要引入另一个全栈框架。已核对官方[安装说明](https://reactrouter.com/start/declarative/installation)和[路由说明](https://reactrouter.com/start/declarative/routing)，安装和导入使用 `react-router`（路由包）。本轮尚未安装。

`BrowserRouter`（浏览器路由容器）提供地址上下文；`Routes`（路由匹配容器）选择匹配项；`Route`（单条路由声明）连接路径和页面。数据请求继续交给现有查询工具，不在本步另外建立一套取数机制。

| 地址 | 内容 |
|---|---|
| `/organizations`（组织列表地址） | 查看、创建组织 |
| `/org/:organizationId`（组织项目列表地址） | 当前组织的项目列表、创建项目 |
| `/project/:projectId`（项目主页地址） | 初始化和检测结果 |
| `/project/:projectId/system`（设计体系地址） | 主题、阶梯、语义与预览 |
| `/project/:projectId/lint`（检查入口地址） | 暂留入口 |

冒号开头的部分是动态参数：实际地址里替换成对应编号。根地址进入组织列表；不存在的地址、组织或项目要显示找不到，不能偷偷选择另一个对象。

2026-10-10 确认项目地址与组织地址并列。参考源码中，组织项目列表使用 `/org/[slug]`，项目页面使用 `/project/[ref]`，见 `supabase-source-guide.md`（参考源码阅读指南）。项目属于哪个组织由项目数据中的 `organizationId`（所属组织编号）表示，不在项目地址里再放一个组织动态段。项目内的设计体系和检查入口仍接在项目地址后面。

## 布局与状态

`AppLayout`（应用布局）提供共享顶栏和组织切换。

`OrganizationLayout`（组织布局）提供组织导航和项目列表所在的内容区域。

`ProjectLayout`（项目布局）提供当前项目、项目侧栏和项目页面所在的内容区域。语义放在设计体系内，不继续作为独立项目页面。

`Outlet`（子页面显示位置）放在布局内容区，让匹配的页面显示进去。这与参考源码给页面包装布局的具体写法不同，但职责相同。路由嵌套按共享布局安排，不必为地址中的每一段都建立一层布局。

当前组织、项目和页面由地址决定，不再同时用组件状态保存一份当前页面编号。输入内容、菜单展开、未保存草稿仍是界面状态；组织和项目列表以后来自服务，由现有查询工具管理。教学开始阶段可先用独立的示例数据走通导航。

组织有编号和名称；项目有编号、名称以及所属组织编号。名称允许修改，不作为关联依据。每份项目草稿按项目编号区分，路由切换本身不会自动保留草稿。

## 怎样跳转

点击组织：进入该组织的项目列表。点击项目：进入项目主页。项目内点击设计体系：保持项目编号，只改变子页面。切换项目：回到新项目主页。切换组织：回到新组织的项目列表。

普通导航使用 `Link`（导航链接），有当前选中态的侧栏使用 `NavLink`（可标记当前页面的导航链接）。创建成功后的跳转使用 `navigate`（程序触发的页面跳转）。这些动作改变地址，让刷新、返回和分享地址具备一致的含义。

后续部署时服务器需要支持把网页路径返回给网页入口；本地开发可先验证直接打开深层地址和刷新。路由不能代替项目持久保存，也不能代替访问权限校验。

## 当前第一小步

先建立组织和项目的最小数据模型，理解归属，暂不改布局和导航。

建议用户在网页自己的模块中手写：

```ts
export type Organization = {
  id: string
  name: string
}

export type Project = {
  id: string
  organizationId: string
  name: string
}
```

`Organization`（组织）与 `Project`（项目）是类型，不是组件。`id`（稳定编号）由系统生成；`organizationId`（所属组织编号）说明项目归属。先提供两个组织和三条项目示例记录。不同组织下同名项目仅为可选理解练习，不是完成条件。

这一小步没有状态，也没有请求：类型描述数据结构，示例数组提供临时数据。编号不重复，每个项目能对应到一个已有组织即可继续，不单独安排一轮验收。
