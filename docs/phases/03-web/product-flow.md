# 本地设计体系编辑工具

## 当前方向：2026-10-12

这版面向开发阶段：设计体系保存在项目文件中，本地网页提供可视化编辑，本地服务负责读取、保存、生成主题和运行检查。启动工具后，用户在网页完成操作；不需要为每次修改再运行一条写回命令。编辑工具关闭后，项目仍使用已经保存的文件。

### 用户流程

在目标项目启动工具 → 打开本地网页 → 读取已有体系或选择起点 → 编辑与预览 → 确认保存 → 本地服务更新文件 → 查看真实项目效果与检查结果。

新项目可以使用工具提供的初始体系，也可以导入另一项目导出的体系。已有主题的项目需先读取并整理定义和语义引用，确认哪些内容可管理、哪些需保留；不能直接覆盖整个样式入口。

保存与生成由本地服务完成。项目自己的开发服务器在样式接入后处理文件变化；编辑器示例预览不能替代真实项目验证。写死值、局部覆盖与变量名称变化仍需扫描和迁移。

下一项目通过复制或导入复用体系，再按自身需要编辑。首版方向是文件复用，不意味着多个项目自动共同更新。

### 页面分工

- 项目入口：展示目标目录、文件读取状态与接入检查，提供创建或导入的入口。目录怎样指定、是否支持同一工具切换多个项目，仍需设计。
- 设计体系：一起管理色板、阶梯、明暗语义和预览，显示草稿与已保存状态。
- 检查：管理对应的检查设置、执行本地源码检查并展示结果。

这些是职责划分，不确定为三条地址或三个独立页面。最终导航在第二阶段开始时确认，不沿用旧组织管理需求作为默认前提。

### 文件与状态分工

| 内容 | 职责 |
| --- | --- |
| 体系定义 | 保存色板、阶梯、语义、明暗模式及检查设置，是网页可以重新打开和复用的内容。 |
| 项目主题 | 供样式构建和页面使用，保留项目本身的布局与组件样式。 |
| 检查配置 | 让本地 `lint`（静态检查）工具按体系检查源码；规则执行程序与规则设置是不同内容。 |
| 编辑草稿 | 未确认的编辑，不代表文件已更新。 |
| 检测结果和恢复记录 | 属于当前项目的操作信息，不混入可复用的设计定义。 |

“独立体系定义文件、生成主题文件”是首选提议，不是已确定文件结构。`design-system.json`（体系定义文件）和 `design-system.generated.css`（生成主题文件）只是此前提议的名字，尚未创建。若采用分离方式，需要明确唯一编辑来源及手改生成文件的处理。

### 仍待设计

具体文件格式与命名、已有主题的导入范围、草稿是否跨重启保存、确认与写入时机、多文件写入失败的恢复、外部修改冲突、规则实现与配置形式、导入后的名称冲突，以及真实项目预览方式，均在对应阶段开始前讨论。

### 当前实现边界

当前代码仍使用 `React Router`（既有路由库）、`Fastify`（既有接口框架）及扫描会话、领取修改的旧流程。新框架、本地读取体系、统一保存、检查生成与文件复用尚未实现。

### 核心能力与流程

1. **启动与进入**：在目标项目目录执行命令启动本地服务，自动唤起浏览器打开本地工作台。
2. **读取与展示**：本地服务读取目标项目的样式文件（CSS 变量）或体系定义（JSON），解析出调色板、阶梯与语义角色并直观展示。
3. **起点选择与体系导入**：
   - 支持从项目当前已有主题开始；
   - 支持一键载入内置的成熟设计体系预设（如 Tailwind / Radix / shadcn 经典风格）；
   - 支持导入外部项目的 `tokens.json` 或指定同机其他项目路径，载入后在前端内存中作为草稿即时全景预览，并提供变量差异对照表（Diff）。
4. **可视化调整与实时预览**：
   - 网页内调节颜色、间距、圆角与明暗语义；
   - 前端通过动态修改 DOM 样式变量实现 0 延迟实时预览，未保存前不修改本地磁盘文件。
5. **安全写回与 Lint 规则生成**：
   - 用户确认保存后，本地服务通过精确 AST（抽象语法树）解析安全写回目标样式文件；
   - 同步生成或更新针对 `@shadcn/lint` / ESLint 规则包的配置文件，禁止硬编码并约束组件代码遵守设计体系。
