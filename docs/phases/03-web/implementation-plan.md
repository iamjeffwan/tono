# 本地编辑工具：开发实施计划

本计划面向开发阶段的本地设计体系编辑与规则生成工具。用户主要手工编写代码；技术负责人负责核对依据、架构分层与取舍；教师一次只解释当前一步，讲清用途、数据来源、状态位置与完成标准。

## 整体实施五阶段

| 阶段 | 阶段目标 | 核心要做的事 | 完成验收标准 | 状态 |
| :--- | :--- | :--- | :--- | :--- |
| **1. 极简闭环骨架** | 打通 CLI 启动器、本地服务与空白页面 | 1. 建立 `CLI`（命令行入口）参数解析与端口监听<br>2. 建立轻量本地服务端并托管静态资源<br>3. 前端空白 `Vite SPA`（单页应用）连通本地接口并自动打开浏览器 | 终端执行启动命令后，自动唤起浏览器打开本地页面，接口返回测试数据正常，构建与类型检查通过。 | 待开始 |
| **2. 本地提取与解析** | 读取目标项目的样式文件与主题变量 | 1. 明确目标文件路径（如 `globals.css` 或 `tokens.json`）<br>2. 服务端使用 `PostCSS`（样式转换工具）提取 `:root` 下的 CSS 变量<br>3. 格式校验与规范化，输出标准变量数据结构 | 服务端接口能精准返回目标项目的色板、阶梯与变量，控制台无报错，错误路径有友好提示。 | 待开始 |
| **3. 前端工作台与实时预览** | 可视化呈现、编辑与 0 延迟预览 | 1. 搭建调色板卡片、间距滑块与语义角色选择器<br>2. 建立前端内存中的**草稿状态（Draft State）**<br>3. 通过动态修改 DOM 样式变量实现实时预览画布，未保存前不修改磁盘 | 拖动调色盘或修改阶梯时，预览组件即时变色；刷新或未保存前不破坏本地物理文件。 | 待开始 |
| **4. 外部设计体系导入与 Diff** | 支持一键应用成熟体系与跨项目复用 | 1. 内置成熟体系预设（如 Tailwind / Radix / shadcn 经典色彩）<br>2. 支持外部 `tokens.json` 拖拽导入与同机路径读取<br>3. 呈现新旧变量差异比对表（Diff）与语义映射确认 | 导入外部体系后，预览区能瞬间呈现整套新风格，并清晰列出新增、替换及冲突变量。 | 待开始 |
| **5. 安全落盘与 Lint 规则生成** | 物理文件更新与代码守门规则闭环 | 1. 前端确认后，服务端通过 AST 安全写回样式文件（保留原有注释与布局样式）<br>2. 自动生成或更新针对 `@shadcn/lint` / `ESLint` 的规则配置文件<br>3. 在业务代码中验证违规拦截效果 | 目标文件变量成功更新；业务代码若硬编码颜色或使用未声明类名，代码检查工具能准确报错。 | 待开始 |

## 协作与指导守则

1. **用户主导手写**：用户是初学者，主要手工写代码。未经明确要求，不替用户代写功能业务代码。
2. **一次只讲一步**：讲清当前一步的用途、数据流向、状态保存在哪、函数签名以及如何验收；一步验证通过后再进入下一步。
3. **术语与名词规范**：组件、库、属性与专业术语必须使用英文名称紧接中文解释（例如：`CLI`（命令行界面）、`AST`（抽象语法树））。
4. **新工具与新命令说明**：引入新库、新组件或执行新命令前，必须先解释用途与使用方法；命令必须解释每个参数的含义。
5. **充分讨论后落盘**：不把未讨论完、未取得共识的方案写进实现。
